# Semantic Validator field-rule evaluation — 2026-09-25

This is a **single run on a small, hand-written, fictional dataset**, not a
production accuracy claim. It used direct BYOK calls to Jev with the SDK
source version 0.3.0, model `jev-latest`, built-in rules v1, and the existing
0.80 confidence threshold. All 90 requests completed; no provider errors
were reported. Each request may have consumed Jev credits. No key, submitted
text, or raw provider response is included here. The complete fictional
[dataset](field-rules.json) and [evaluation method](README.md) are public.

| Rule | Labeled cases | Matched labels | False positives | False negatives | Uncertain labeled | Ambiguous: valid / invalid / uncertain |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `person_name` | 24 | 24 | 0 | 0 | 0 | 5 / 0 / 1 |
| `product_description` | 24 | 24 | 0 | 0 | 0 | 1 / 2 / 3 |
| `address` | 24 | 23 | 0 | 0 | 1 | 1 / 3 / 2 |
| **Total** | **72** | **71** | **0** | **0** | **1** | **7 / 5 / 6** |

Each rule had 12 positive, 12 negative, and 6 intentionally ambiguous cases.
Ambiguous cases have no right/wrong label and are **excluded** from the 72
labeled cases. `address-p02` was the one labeled case returned as `uncertain`.
Thus 71/72 labeled cases matched and 1/72 was deferred; this fraction is
**not an estimate of accuracy on real-world input**. The dataset is curated,
small, and not sampled from any production population. It also has one human
label per case, no inter-annotator agreement, and only one full Jev run.

The ambiguous cases matter: 12/18 received `valid` or `invalid`, sometimes
with high confidence. A confidence threshold of 0.80 is not an ambiguity
detector. The [earlier nine-case pilot](PILOT-2026-09-25.md) also produced a
different result for `name-a01` (pilot: `valid`, 0.81; full run: `uncertain`,
0.78), so identical inputs can vary between runs. Do not use these results
to claim a guarantee or to automatically reject people, products, or addresses.

To reproduce the selection without a key or network access:

```bash
python3 tools/evaluate.py --cases evals/field-rules.json --dry-run
```

For a live rerun, see [the evaluation guide](README.md). It requires your own
Jev key and can consume another 90 requests. Results may change as the
provider/model changes. The next quality step is testing representative,
consented application data and repeating runs before tuning prompts or
thresholds.
