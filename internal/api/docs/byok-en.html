SDK guide · bring your own Jev key

Validate meaning
without our server.

Use your own TypeSafe/Jev account from a trusted backend. The SDK sends text straight to Jev and returns valid, confidence, and status. No account or key from us is needed. The API hosted on this domain remains paused.

01 / Start

Get your own Jev key

The source is free and open source under Apache-2.0. Create a key in your own TypeSafe account and make it available as TYPESAFE_API_KEY to your backend process. Do not commit it, paste it into frontend code, or share it with us. TypeScript, Python, and Java SDKs are not yet published to npm, PyPI, or Maven Central; the Go SDK is part of the public Go module.

The three built-in field rules are person_name, product_description, and address; use check(value, question) for other semantic questions. Confidence below 0.80 produces status="uncertain" and valid=null. Each batch item calls Jev separately and is charged to your account.

02 / How to use

From text to a decision

After installing an SDK, create a DirectValidator (or NewDirectClient in Go) with your Jev key. Call validate("product_description", text) for a registered rule, or check(text, question) for your own yes/no question. Read status before acting: uncertain means valid is null and needs review; an exception or error means the request failed, not that the text is invalid. A complete example for each language follows. A .env file is not loaded automatically: make sure TYPESAFE_API_KEY is available to your process.

Open evaluation

What the rules did in one test

In a single run of 90 fictional cases, 71 of 72 labeled cases matched; one was uncertain, with no provider errors. Ambiguous cases were tracked separately. This is not a real-world accuracy claim. Read the full results and limitations.

03 / SDKs

Choose your language

Try the four runnable projects without a Jev key. The TypeScript form example shows all three rules and treats uncertain results and provider failures separately.

TypeScript / Node.js

Download the TypeScript SDK (.tgz). Node.js 18+; run on the server, never in a browser.

npm install ./semantic-validator-sdk-0.3.0.tgz
npm install -D tsx @types/node

Save as prueba.ts and run npx tsx prueba.ts:

import { DirectValidator } from "@semantic-validator/sdk";

const jevApiKey = process.env.TYPESAFE_API_KEY;
if (!jevApiKey) throw new Error("Missing TYPESAFE_API_KEY");
const validator = new DirectValidator({ jevApiKey });

async function main() {
  const product = await validator.validate(
    "product_description", "Bosch 750 W power drill"
  );
  const complaint = await validator.check(
    "My order arrived damaged and I need a solution",
    "Is the customer making a complaint?"
  );
  for (const [field, result] of [["product", product], ["complaint", complaint]] as const) {
    if (result.status === "uncertain") console.log(field, "needs review");
    else console.log(field, result.valid, result.confidence);
  }
}

main().catch((error) => {
  console.error("Validation request failed:", error);
  process.exitCode = 1;
});

Python

Download the Python SDK (.tar.gz). Python 3.10+.

tar -xzf semantic-validator-python-0.3.0.tar.gz
python3 -m venv .venv
source .venv/bin/activate
python -m pip install ./semantic-validator/sdk/python

Save as prueba.py and run python prueba.py:

import os
from semantic_validator import DirectValidator

def show(field, result):
    if result.status == "uncertain":
        print(field, "needs review")
    else:
        print(field, result.valid, result.confidence)

validator = DirectValidator(jev_api_key=os.environ["TYPESAFE_API_KEY"])
try:
    show("name", validator.name("Jorge Eduardo"))
    show("complaint", validator.check(
        "My order arrived damaged and I need a solution",
        "Is the customer making a complaint?"
    ))
except Exception as error:
    raise SystemExit(f"Validation request failed: {error}") from error

Go

Go 1.22+. Install from the public Go module, or download the Go SDK source archive (.tar.gz).

mkdir go-example && cd go-example
go mod init go-example
go get github.com/eduardoArequipa/semantic-validator/sdk/go@v0.3.0

Save as main.go, then run go run .:

package main

import (
  "context"
  "fmt"
  "log"
  "os"
  validator "github.com/eduardoArequipa/semantic-validator/sdk/go"
)

func main() {
  client, err := validator.NewDirectClient(os.Getenv("TYPESAFE_API_KEY"))
  if err != nil { log.Fatal(err) }
  name, err := client.Name(context.Background(), "Jorge Eduardo")
  if err != nil { log.Fatal(err) }
  complaint, err := client.Check(context.Background(),
    "My order arrived damaged and I need a solution",
    "Is the customer making a complaint?")
  if err != nil { log.Fatal(err) }
  show("name", name)
  show("complaint", complaint)
}

func show(field string, result validator.Result) {
  if result.Status == "uncertain" {
    fmt.Println(field, "needs review")
    return
  }
  fmt.Println(field, *result.Valid, result.Confidence)
}

Java

Download the Java SDK (.tar.gz). Java 11+ and Maven.

tar -xzf semantic-validator-java-0.3.0.tar.gz
mvn -f semantic-validator/sdk/java/pom.xml install

Add the local dependency to your Maven application's pom.xml:

<dependency>
  <groupId>io.semanticvalidator</groupId>
  <artifactId>semantic-validator-sdk</artifactId>
  <version>0.3.0</version>
</dependency>

Save as Example.java in your Maven application and run it there:

import io.semanticvalidator.sdk.DirectValidator;
import io.semanticvalidator.sdk.ValidationResult;

public class Example {
  public static void main(String[] args) {
    String key = System.getenv("TYPESAFE_API_KEY");
    if (key == null || key.isBlank()) throw new IllegalStateException("Missing TYPESAFE_API_KEY");
    DirectValidator validator = new DirectValidator(key);
    try {
      show("name", validator.name("Jorge Eduardo"));
      show("complaint", validator.check(
        "My order arrived damaged and I need a solution",
        "Is the customer making a complaint?"));
    } catch (Exception error) {
      System.err.println("Validation request failed: " + error.getMessage());
      System.exit(1);
    }
  }

  static void show(String field, ValidationResult result) {
    if ("uncertain".equals(result.getStatus()))
      System.out.println(field + ": needs review");
    else
      System.out.println(field + ": " + result.getValid() + " (" + result.getConfidence() + ")");
  }
}

04 / Optional

Run your own API server

If you need an HTTP API or central quotas, run the Go server on your infrastructure with your own TYPESAFE_API_KEY. Then set a separate SEMANTIC_VALIDATOR_API_KEY for its callers and use the legacy Validator clients. The server is not required for direct mode.

cp .env.example .env
# Set both keys in .env; keep it private.
set -a; source .env; set +a
go run ./cmd/server
# Own server only: http://localhost:8080/v1/check

See the OpenAPI contract for your own server. Never send a Jev key as its Semantic Validator API key.

05 / Responsible use

Protect keys and user text

Direct calls require a trusted backend. The text goes to Jev, not to this website. Avoid real personal data in public examples. Apache-2.0 covers our code, not Jev; use your own TypeSafe account subject to its terms. Our hosted API remains disabled and this site serves documentation only.
